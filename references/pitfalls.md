# 踩坑表与验收门禁

这一篇全部来自真实项目的实战返工，每一条都给出**现象 → 根因 → 解法 → 检测方法**。动手前扫一眼，交付前照门禁走一遍。

---

## 一、引擎行为类

### 坑 1 · `IN` 被当成 JS 运算符，英文眉标折行

**现象**：`// IN MEMORY` 渲染成两行（`// IN` / `MEMORY`），其余页面正常。

**根因**：slidep 的 DSL 解析器把独立词 `in` 当成 JS 的 `in` 运算符关键字。排除法确认：同页的 `// THE SPIRIT`、`// DEEP DIVE 1988` 都单行，只有含 `IN` 的那行折行。

**解法**：英文眉标里禁用 `in` / `IN` 及其变形。改用同义短语：`// IN MEMORY` → `// REMEMBRANCE`。

**检测**：`grep -niE '\bin\b' slides/*.slide` 命中即需人工确认。

> 适用范围：任何英文标签。中文不存在这个问题。

---

### 坑 2 · 相邻独立 `<Text>` 的间距被放大

**现象**：两段本该紧挨着的正文之间凭空多出约 50px 空隙，视觉上像多了一行。

**根因**：引擎对**相邻的两个独立 `<Text>`** 的间距处理异常。已验证无效的解法：`justifyContent: 'flex-start'`、`flexShrink: 0`、给父容器固定高度。

**解法**：**合并为一个 `<Text>`，段内用 `<br/>` 换行。**

```jsx
{/* ✗ 两段之间会多出空隙 */}
<Text style={{...}}>第一段……</Text>
<Text style={{...}}>第二段……</Text>

{/* ✓ 合并，行距均匀 */}
<Text style={{...}}>第一段……<br/>第二段……</Text>
```

**检测**：看渲染图，两段之间若有一整行的空白，就是这个坑。

---

### 坑 3 · 固定高度容器 + `marginTop: 'auto'` 在溢出时把后置块顶上来

**现象**：卡片里列表项和下方说明段**直接重叠**，文字叠在一起。

**根因**：卡片写死了 `height`，内容超出后，`marginTop: 'auto'` 的后置块被推到容器顶而不是底部，压在前文上。

**解法**：容器高度按内容算准；`marginTop: 'auto'` 换成**固定值**（如 18）。

```jsx
{/* ✗ */}
<Box style={{ height: 404, flexDirection: 'column' }}>
    <Text>...</Text>
    <Box style={{ marginTop: 'auto' }}>...</Box>
</Box>

{/* ✓ 高度算够 + 固定间距 */}
<Box style={{ height: 440, flexDirection: 'column' }}>
    <Text>...</Text>
    <Box style={{ marginTop: 18 }}>...</Box>
</Box>
```

**检测**：`slidep lint` 会报溢出；像素扫描也会发现异常空白带。

---

### 坑 4 · 行高装不下换行，内容压到下一行

**现象**：时间轴里某一行的小标换了行，第二行文字直接压在下一条记录上。

**根因**：行高按单行算的，但小标在定宽列里换行了。

**解法**：三选一 —— 加高行高（66 → 70）、加宽标题列（292 → 310）、**把标题缩短到不换行**。最优是缩短标题：`「毕业于国立交通大学造船系」→「毕业于国立交大造船系」`。

**检测**：逐页看渲染图，发现某行有异常高度就查这一行。

## 二、工具链类

### 坑 5 · 图片根目录是 PPTX 所在目录

**现象**：DSL 里 `src="assets/photo.jpg"` 渲染不出来。

**根因**：引擎以 **PPTX 所在目录**为图片根目录，不是 DSL 文件所在目录。

**解法**：`assets/` 必须与 pptx **同级**。构建时如果 pptx 在 `_variants/` 下，就得把 `assets/` 也复制到 `_variants/`。

**检测**：`slidep screenshot` 出来的图那块是灰底（`#E4E4E0`）就是图没找到。

---

### 坑 6 · `upsert-dsl` 会静默失败

**现象**：改完 DSL 重新构建，截图内容和改动前**一模一样**，但命令退出码是 0。

**根因**：`upsert-dsl` 失败时不报错，截图照样生成（渲染的是旧页面）。

**解法**：**每次 upsert 后必须做像素差分校验**：

```python
from PIL import Image, ImageChops
old = Image.open('before.png').convert('RGB')
new = Image.open('after.png').convert('RGB')
diff = ImageChops.difference(old, new)
assert diff.getbbox() is not None, "页面没变化 —— upsert 静默失败了"
```

> 教训：没有像素校验的对比实验，结论一律不可信。本项目曾因此连错两轮实验方向。

**检测**：同上。

---

### 坑 7 · `presentation is not open` 瞬时故障

**现象**：批量构建时偶发报错。

**根因**：引擎的瞬时状态。

**解法**：**重试 4 次，每次间隔 2 秒**。`build_deck.py` 已内置。

---

### 坑 8 · Windows 文件锁导致覆盖失败

**现象**：`PermissionError: [Errno 13] Permission denied`，覆盖 `.pptx` 时失败。

**根因**：文件被预览进程占用。

**解法**：**不覆盖，换新文件名**（如加日期后缀）。不要反复重试覆盖。

---

### 坑 9 · 自闭合标签干扰区间配对

**现象**：解析 DSL 找某个 Box 的闭合位置时，跨到了兄弟节点。

**根因**：自闭合的 `<Box ... />` 被当成开标签。

**解法**：配对区间时**排除自闭合标签**。

## 三、视觉与可读性类

### 坑 10 · 深色底上用 `ink2` 写次级文字

**现象**：深红页上的灰色说明文字几乎看不见。

**根因**：`#5C5C5C` 压在 `#161616` 上只有 2.6:1。

**解法**：深色底的次级文字用 `#A3A3A3`（约 5.4:1）。

---

### 坑 11 · 图注条文字溢出被裁

**现象**：照片下方的深色条带里，最后一个字被切掉一半。

**根因**：条带内可用宽 448px，实际文字宽 457px，右边距只剩 3.3px。

**解法**：**缩短文案**（不要缩字号 —— 16px 是下限）。像素实测：

```python
row = np.array(Image.open(p).convert('RGB')).astype(int)[y]
band = np.where((abs(row[:,0]-166)<25)&(abs(row[:,1]-43)<30))[0]  # 深红条带范围
bright = np.where(row[band.min():band.max()+1].sum(axis=1) > 430)[0]
right_margin = (band.max() - (bright.max()+band.min())) / 1.5
print(right_margin, "幻灯片 px")   # 小于 8 就有裁切风险
```

**检测**：`scan_overflow.py` 会扫这个。

---

### 坑 12 · 强调色满版铺底

**现象**：整页铺满强调色后，强调色的「醒目」含义消失了，页面变成色块广告。

**解法**：按 `accent_gen.py` 给的面积上限控制（深色强调色 ≤40%，浅色强调色 ≤15%）。高潮页优先用**左色右浅**（强调色占 37.5%）。

---

### 坑 13 · `inspect` 输出是 Markdown，下划线被转义 → 校验误报「文本未写入」

**现象**：`build_deck.py` 报「第 1 页文本未写入（可能 upsert 静默失败）」，但 `slidep inspect` 里那句话明明在。

**根因**：`inspect` 输出的是 Markdown，`accent_gen` 会被转义成 `accent\_gen`；校验前只去掉了空白，没还原反斜杠，于是比对失败。

**解法**：比对前先还原转义（`re.sub(r"\\(.)", r"\1", s)`）再删空白。`build_deck.py` 的 `norm()` 已按此实现 —— **如果你自己写校验脚本，别忘了这一步**。

**教训**：校验器自身的 bug 会伪装成产物 bug。校验器报未写入时，先 `slidep inspect` 眼看一眼，再决定是产物问题还是校验器问题。

## 四、验收门禁（四步，全过才算完成）

### 第 1 步 · lint 零诊断

```bash
for f in slides/*.slide; do
  slidep lint deck.pptx --dsl-file "$f"
done
```

**要求**：每一页 `diagnostics: []`。有诊断就按提示改，别绕过。

### 第 2 步 · 逐页截图 + 人工复检

```bash
for i in 0 1 2 ...; do
  slidep screenshot deck.pptx --page-index $i --out shot_$i.png
done
```

**必查项**（每一页）：

- [ ] 无文字溢出容器、无重叠、无裁切
- [ ] 无异常大空白（正文段落之间）
- [ ] 强调色面积在上限内
- [ ] 深色底上的文字是浅色
- [ ] 页眉编号块、页脚页码位置一致
- [ ] 英文眉标单行（没有 `in` 折行）

### 第 3 步 · 像素扫描

```bash
python scripts/scan_overflow.py --pptx deck.pptx --slides slides/
```

自动扫：异常空白带、图注条裁切风险、深色底上的低对比文字。

### 第 4 步 · 产物完整性

- [ ] `python-pptx` 能正常打开，页数正确
- [ ] 每页都有 notes（演讲备注）
- [ ] 媒体引用 **0 断链**
- [ ] 讲稿 docx 的缩略图与 PPT 终版一致（逐张 MD5 校验）
