# 主题色：任意切换的规则与算法

这一篇解决一个问题：**用户说「用红色」「用科技蓝」「用我们公司的品牌色」，怎么把它变成一整套能看的配色，而不是随手把一个 hex 填进去。**

原 endfield-ui skill 的 accent 维度只给了 4 个预设（yellow / lime / ice / amber），并明文写着「不能是红、粉红」。本篇把它改成：**任意色都能进，但必须过三道闸 —— 语义闸、对比度闸、面积闸。**

---

## 一、换色的完整流程

```
① 拿到色值            用户给 hex / 中文色名 / 品牌手册
        ↓
② 语义闸              这个色在项目里有没有既定含义？（红=删除）
        ↓
③ 派生                accent → deep / soft / tint 三个派生色
        ↓
④ 对比度闸            四组 WCAG 实测 → 自动决定前景色
        ↓
⑤ 面积闸              允许铺多大比例的底
        ↓
⑥ 写变体卡            交付说明的第一屏
```

**不要手算，不要凭感觉。** 直接跑：

```bash
python scripts/accent_gen.py "#A62B1F" --name 深红
```

它会一次性给出上面全部六步的结论，并附一张可直接贴进交付说明的变体卡。

---

## 二、语义闸：红色不是禁用，是条件式

原 skill 的固定规则里有一条「红色只给删除」。这条规则的**前提**是：红色在界面里已经有一个稳定的既定含义 —— 不可撤销。如果项目里根本没有删除、危险、撤销类操作，这个前提就不成立，红色可以被释放出来当强调色。

判定分三种情况：

| 项目里有删除/危险/撤销语义 | 红色能否作强调色 | 怎么办 |
|---|---|---|
| **有** | **不能** | 红色保留给删除，强调色另选（跑 `--suggest` 看替代色） |
| **无** | 能，但要写豁免 | 变体卡里写明「本片无删除语义，红色由 danger 语义释放为强调色」，并保证页面上不出现任何删除类操作 |
| 不确定 | 先按「有」处理 | 有疑问时宁可保留红色的删除含义 |

引擎的判定：

```bash
python scripts/accent_gen.py "#A62B1F"                  # → 语义判定：已释放
python scripts/accent_gen.py "#A62B1F" --has-delete     # → 语义判定：禁止使用（退出码 2）
```

**释放了红色之后的一条硬约束**：整套片子里不能有任何红色元素表示「危险/删除」。一旦有一处红按钮，观众对红色的解读就回到「危险」，强调色的含义当场作废。

粉红、桃粉这类接近红色的色相（色相 340°–20°）同样受这条约束。

## 三、对比度闸：四组读数，一次算完

只看「黑字压上去够不够」是不够的。一个色在不同底上有四种用法，必须分别算：

| 读数 | 用途 | 合格线 |
|---|---|---|
| 墨字 `#161616` 压 accent | accent 上放墨色文字 | 4.5:1 |
| 白字 `#FFFFFF` 压 accent | accent 上放白色文字 | 4.5:1（≥7 更好） |
| accent 作字压纸底 `#F4F4F2` | 浅底上用 accent 写正文 | 4.5:1 |
| accent 作线压墨底 `#191919` | 深色主题里画当前位置标记 | 3.0:1 |

引擎自动做三件事：

1. **算四组读数**并标注可用/不可用
2. **决定前景色**：accent 底上的字用墨色还是白色，取对比度高的那个（必须 ≥4.5）
3. **给结论**：能不能满版铺底、能不能当文字用、深底里能不能用

一个真实例子（`#A62B1F`）：

```
  墨字 #161616 压 accent      2.57:1    不可用 —— 墨色压不住这个色
  白字压 accent               7.03:1    可用
  accent 作字压纸底           6.38:1    可用
  accent 作线压墨底           2.50:1    不可用 —— 深色页里强调线要换白色
```

由此推出两条硬规则：

> **规则 1**：accent 底上的文字一律走引擎决策出来的 `fore` 色，不许手写。
> **规则 2**：深色底（墨底 `#191919` 或深红满版页）里，强调线/强调字**不能用 accent**，改用白色。

第 2 条是从「accent 作线压墨底 = 2.50:1」直接推出来的 —— 深红页上的红色装饰线等于隐形。

## 四、派生色板：三个派生色 + 一个前景色

一个强调色要撑起整套片子，需要四个值：

| 名称 | 用途 | 派生方式 |
|---|---|---|
| `accent` | 小块填充：编号块、数据徽标、分隔短线、按钮 | 用户给的值 |
| `deep` | 满版底色（高潮页） | 保持色相压暗一档，且**白字压上去 ≥7:1** |
| `soft` | 浅底上的强调块 | 保持色相提亮到**墨字刚好压得住**的最深位置 |
| `tint` | 极淡背景纹理 | 保持色相，明度拉到 0.93，只作质感 |
| `fore` | accent 上的文字色 | 引擎自动决策（墨 or 白） |

**派生必须在 HSL 空间做，不能用 RGB 混白。** RGB 混白会让红色发灰粉（`#A62B1F` 混白 86% 得到 `#D1918B`，色相基本丢光），HSL 空间保持色相，得到的浅红 `#E18A81` 一眼就知道是同一个红。

`deep` 的算法是「刚好合规」而不是拍固定系数：先试比 accent 深 0.10，若白字仍 ≥7:1 就用它，否则继续往下压。换一个更亮的强调色时，这条规则自动适配，不用改代码。

```bash
python scripts/accent_gen.py "#A62B1F" --format json   # 拿结构化色板
```

## 五、面积闸：强调色不能铺满

原 skill 有一条「强调色只做填充，从不大面积铺底」。这条对所有色成立，包括红色 —— 但红色特别容易被误用，因为「红色满版」看起来很有气势，实际上它把强调色的含义稀释了，等于没有强调色。

引擎给出的上限：

| accent 的情况 | 能否满版 | 面积上限 |
|---|---|---|
| 浅色（黄、荧光绿、浅橙，前景色是墨） | **不能** | ≤15%，只做小块 |
| 深色，白字压上 ≥7:1 | 能 | ≤40% |
| 深色，4.5 ≤ 白字压上 < 7 | 能，但文字必须全白且 ≥24px | ≤25% |
| 深色，白字压上 < 4.5 | 不能，用 `deep` 作满版底 | ≤15% |

**「满版页」的正确做法**：不是把 accent 铺满，而是**限制它在一侧**。实测有效的做法是「左红右浅」—— 左侧一条深色面板承载巨型数字或引文，右侧留纸底放正文，强调色占 37.5%，既保留气势又不喧宾夺主。

## 六、变体卡

每次交付的第一屏都要有这张卡。引擎的 `--format text` 会直接生成可用文本，格式：

```text
变体：深红（#A62B1F / neutral / standard / contours / standard / calm）
主视觉：待定（从自己的内容里来，不用模板占位）
页面类型：封面展示 + 内容阅读 + 高潮页 + 收尾
强调色只做填充；accent 上写 #FFFFFF 字；满版页用 #7E1D14
红色豁免：本片无删除/危险/撤销语义，红色由 danger 语义释放为强调色
```

六个维度的顺序固定：**accent / paper / cut / ground / density / motion**。其他维度沿用原 skill 的定义：

| 维度 | 本包常用取值 | 说明 |
|---|---|---|
| paper | `neutral` / `warm` / `cool` | 只微调纸、板、细线、浅块；墨色与次级文字不变 |
| cut | `standard` | PPT 里基本不用切角（静态投影） |
| ground | `contours` | 等高线纹理，浅底用墨版、深底用白版 |
| density | `standard` | 投影场景建议 `standard` 或 `roomy` |
| motion | `calm` | PPT 静态，无入场动效 |

## 八、色彩方案对比与替代推荐

手上有几个候选色时，先排行再选：

```bash
python scripts/accent_gen.py compare "#A62B1F" "#FFFA00" "#1E6FFF" "#0F9D76"
```

输出会同时给出四组读数、前景色、语义状态和一句结论（如「可满版 / 深底勿用」「只做小块 / 不可作字」）。

某个色不合格时，找最近的合格替代：

```bash
python scripts/accent_gen.py suggest "#F2789F"
```

替代色按「离原色最近」排序，而不是按对比度最高排序 —— 否则会推出一堆接近白色的无用色。

## 九、禁忌

- 不要手算对比度，不要凭眼睛判断「看着挺清楚」。
- 不要手写 `fore` 色，用引擎决策值。
- 不要在 RGB 空间混白派生浅色，会丢色相。
- 不要让 accent 在满版页里既做底色又做文字色（那是 accent 压 accent，永远不达标）。
- 不要在一套片子里同时用两种强调色。
- 不要用 `deep` 以外的颜色做满版底 —— `deep` 是唯一保证白字达标的派生色。
- 释放红色之后，不要在片子里出现任何删除/危险语义的操作。
